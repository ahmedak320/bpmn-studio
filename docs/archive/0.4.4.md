## 0.4.5 release-control handoff

The release repository has immutable releases enabled. Active tag ruleset
`19784615`, `OrbitPM protected v* release tags`, applies creation, update, and
deletion controls to `refs/tags/v*`. Its sole always-bypass entry is
`RepositoryRole` actor ID `5` (the repository administrator role). The
workflows fail closed unless repository variables
`ORBITPM_RELEASE_TAG_RULESET_ID=19784615` and
`ORBITPM_RELEASE_TAG_BYPASS_ACTOR_ID=5` match that live state.

The protected lifecycle environments and their exact policy variables are:

`ORBITPM_RELEASE_ADMIN_TOKEN` is an environment secret only in
`release-v0.4.5` and `release-finalize-v0.4.5`; it must not exist as a
repository secret or in Pages, rollback, or cleanup environments. The
automatic rollback environment is main-only, reviewer-free, and secret-free.
The release, Pages, finalization, cleanup, and manual rollback environments
require independent reviewers, prevent self-review, and disallow administrator
bypass. Replace the current owner-only reviewer placeholder with an independent
authorized reviewer before dispatching any protected job.

The pre-tag pull-request gate requires that independent reviewer to have
repository write permission. After the pre-tag approval and candidate workflow
finish, downgrade the reviewer to read permission while retaining them as an
environment reviewer; only then dispatch release finalization. This preserves
independent protected-environment approval while satisfying the finalizer's
owner-only push-capable collaborator check. Main branch protection separately
requires one approval and approval of the latest push.

GitHub's release update API has no conditional compare-and-swap operation.
From the final pre-publication read through immutable stable read-back, the
sole owner must therefore freeze all manual, API, CLI, and installed-app
release writes. The finalizer verifies the configured sole writer and rejects
concurrent release, finalization, or cleanup workflow runs, but that operational
freeze remains mandatory. External human evidence URL/SHA inputs are collected
after the candidate gate; post-Pages browser-compatibility URL/SHA inputs are
collected only after the exact Pages bytes have been verified.

## Baseline verification

The archival baseline recorded passing Desktop and Lite typechecks, 248 Desktop
unit tests, 1,257 Lite unit tests, and a Lite single-file build. Its Chromium
artifact suite passed 62 tests with three live-network tests skipped, and a
separate run reproduced the known 0.4.4 free-translation 429 race.

That baseline evidence preserves history; it does not satisfy the 0.4.5
no-skip/no-flake release gate.
